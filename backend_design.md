# تصميم هيكلية الـ Backend لتطبيق Flutter Fashion App

## 1. الملخص التنفيذي

يهدف هذا المستند إلى تحديد وتصميم هيكلية الجزء الخلفي (Backend) لتطبيق Flutter Fashion App. سيتضمن التصميم المقترح نماذج البيانات (Database Schema)، ونقاط نهاية واجهة برمجة التطبيقات (API Endpoints)، وآليات المصادقة (Authentication) والترخيص (Authorization) اللازمة لدعم جميع الميزات الموضحة في واجهة المستخدم الأمامية (Frontend) لتطبيق Flutter.

## 2. التقنيات المستخدمة

*   **لغة البرمجة:** Node.js
*   **إطار العمل:** Express.js
*   **قاعدة البيانات:** PostgreSQL (أو MySQL كبديل)
*   **إدارة الحزم:** npm/yarn
*   **المصادقة:** JWT (JSON Web Tokens)

## 4. نقاط نهاية واجهة برمجة التطبيقات (API Endpoints)

سيتم تنظيم نقاط نهاية API بشكل منطقي لدعم العمليات المختلفة في التطبيق. سيتم استخدام `JWT` للمصادقة في جميع نقاط النهاية المحمية.

### 4.1. المصادقة (Authentication)

*   `POST /api/auth/register`: تسجيل مستخدم جديد.
    *   **الطلب:** `{ username, email, password }`
    *   **الاستجابة:** `{ token, user: { id, username, email } }`
*   `POST /api/auth/login`: تسجيل دخول المستخدم.
    *   **الطلب:** `{ email, password }`
    *   **الاستجابة:** `{ token, user: { id, username, email } }`
*   `GET /api/auth/me`: الحصول على معلومات المستخدم الحالي (محمي).
    *   **الاستجابة:** `{ id, username, email }`

### 4.2. المستخدمون (Users)

*   `GET /api/users/:id`: الحصول على معلومات مستخدم معين (محمي).
*   `PUT /api/users/:id`: تحديث معلومات المستخدم (محمي).
    *   **الطلب:** `{ username, email, password }` (اختياري)
*   `GET /api/users/:id/addresses`: الحصول على عناوين المستخدم (محمي).
*   `POST /api/users/:id/addresses`: إضافة عنوان جديد للمستخدم (محمي).
*   `PUT /api/users/:id/addresses/:addressId`: تحديث عنوان المستخدم (محمي).
*   `DELETE /api/users/:id/addresses/:addressId`: حذف عنوان المستخدم (محمي).
*   `GET /api/users/:id/payment-methods`: الحصول على طرق دفع المستخدم (محمي).
*   `POST /api/users/:id/payment-methods`: إضافة طريقة دفع جديدة للمستخدم (محمي).
*   `PUT /api/users/:id/payment-methods/:methodId`: تحديث طريقة دفع المستخدم (محمي).
*   `DELETE /api/users/:id/payment-methods/:methodId`: حذف طريقة دفع المستخدم (محمي).

### 4.3. المنتجات (Products)

*   `GET /api/products`: الحصول على جميع المنتجات (مع دعم التصفية والفرز والبحث).
    *   **معلمات الاستعلام:** `?category=footwear&sort=price_asc&search=shoe`
*   `GET /api/products/:id`: الحصول على تفاصيل منتج معين.
*   `GET /api/categories`: الحصول على جميع فئات المنتجات.

### 4.4. قوائم الرغبات (Wishlists)

*   `GET /api/wishlist`: الحصول على قائمة رغبات المستخدم الحالي (محمي).
*   `POST /api/wishlist`: إضافة منتج إلى قائمة رغبات المستخدم (محمي).
    *   **الطلب:** `{ productId }`
*   `DELETE /api/wishlist/:productId`: إزالة منتج من قائمة رغبات المستخدم (محمي).

### 4.5. سلة التسوق (Cart) - (ملاحظة: يمكن إدارتها على الواجهة الأمامية أو الخلفية، سنفترض هنا أنها تدار على الواجهة الخلفية لتوفير حالة متسقة)

*   `GET /api/cart`: الحصول على سلة تسوق المستخدم الحالي (محمي).
*   `POST /api/cart`: إضافة منتج إلى سلة التسوق (محمي).
    *   **الطلب:** `{ productId, quantity }`
*   `PUT /api/cart/:productId`: تحديث كمية منتج في سلة التسوق (محمي).
    *   **الطلب:** `{ quantity }`
*   `DELETE /api/cart/:productId`: إزالة منتج من سلة التسوق (محمي).

### 4.6. الطلبات (Orders)

*   `POST /api/orders`: إنشاء طلب جديد (محمي).
    *   **الطلب:** `{ shippingAddressId, paymentMethodId, items: [{ productId, quantity }] }`
*   `GET /api/orders`: الحصول على جميع طلبات المستخدم الحالي (محمي).
*   `GET /api/orders/:id`: الحصول على تفاصيل طلب معين (محمي).

### 4.7. المراجعات (Reviews)

*   `GET /api/products/:productId/reviews`: الحصول على مراجعات منتج معين.
*   `POST /api/products/:productId/reviews`: إضافة مراجعة لمنتج (محمي).
    *   **الطلب:** `{ rating, comment }`

## 5. المصادقة والترخيص (Authentication and Authorization)

*   **المصادقة:** سيتم استخدام `JSON Web Tokens (JWT)` للمصادقة. عند تسجيل الدخول أو التسجيل بنجاح، سيتم إصدار رمز JWT للمستخدم، والذي يجب تضمينه في رأس `Authorization` (كـ `Bearer Token`) لجميع الطلبات المحمية.
*   **الترخيص:** سيتم تطبيق الترخيص على مستوى نقطة النهاية (Endpoint-level) لضمان أن المستخدمين المصادق عليهم فقط يمكنهم الوصول إلى الموارد الخاصة بهم (مثل ملفهم الشخصي، طلباتهم، قائمة رغباتهم). سيتم التحقق من `user_id` في رمز JWT مقابل `user_id` للمورد المطلوب.

## 6. اعتبارات إضافية

*   **التحقق من صحة المدخلات (Input Validation):** سيتم تطبيق التحقق الصارم من صحة المدخلات على جميع نقاط نهاية API لمنع البيانات غير الصالحة أو الضارة.
*   **معالجة الأخطاء (Error Handling):** سيتم تنفيذ معالجة أخطاء شاملة لتوفير رسائل خطأ واضحة ومفيدة للواجهة الأمامية.
*   **الأمان (Security):** سيتم استخدام أفضل الممارسات الأمنية، بما في ذلك تجزئة كلمات المرور (hashing passwords) باستخدام `bcrypt`، وحماية نقاط نهاية API، وتشفير البيانات الحساسة (مثل تفاصيل الدفع).
*   **التوثيق (Documentation):** سيتم توثيق API باستخدام أدوات مثل Swagger/OpenAPI لتسهيل فهم واستخدام الواجهة الأمامية.
